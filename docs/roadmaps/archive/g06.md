# Generation g06 — Runtime Recovery and Feature Breadth (roll-up)

Status: archived

Active: 2026-03-13 → 2026-03-16 (closed)
Successor: `g07`

## Intent and boundary

Supply deeper runtime recovery truth, actionable execution instrumentation,
broader real plugin/backend functionality, stronger hardware and media
services, and integrated soak evidence — without pushing those concerns back
into product hosts. Mixed hardening and feature breadth deliberately: runtime
interruption/resumability/recovery semantics, profiling and deferred-work
policy, VST3/AU/Linux plugin coverage, MIDI/event expansion, explicit
plugin-isolation policy, hardware supervision and external I/O, media
services, and shared acceptance evidence for Loophole.

## Shipped outcomes

- Runtime recovery and continuity: interruption taxonomy and resumability
  contract, recording continuity and checkpoint truth, plugin isolation
  policy with transport rebind and shared-sandbox continuity, offline-render
  recovery, fault-cause attribution (`g06.001`–`g06.005`; Contract `014`
  family).
- Execution instrumentation: per-block timing and pressure snapshots,
  graph critical-path and worker-lane instrumentation, deferred-work
  scheduler policy (`g06.006`–`g06.008`).
- Plugin-format breadth: VST3 and AU adapter baselines with runtime-owned
  lifecycle, backend capability parity and cross-adapter conformance, generic
  MIDI/note-expression/event model, presets and portable recall (`g06.009`–
  `g06.013`).
- Hardware and external I/O: device supervision and restart state machines,
  clock-domain and endpoint topology, monitoring tap points and loopback
  measurement (`g06.014`–`g06.016`).
- Media services, acceptance, and closeout: media indexing and preview
  services, analysis metadata extraction, fault-injection harnesses,
  multi-backend acceptance, long-session soak and Loophole-readiness
  closeout (`g06.017`–`g06.020`).

## Canonical destinations
