## Intent and boundary

Turn audit findings into a contract-backed realization, hardening, and
interactive-proof program. The post-`g08` audit exposed breadth that was
contract-deep but implementation-thin, plus oversized runtime surfaces with
implicit failure behavior. `g09` replaced scaffolded plugin and
native-backend implementations with real discovery and execution, removed
duplicated host recovery logic, decomposed oversized runtime surfaces,
hardened low-level correctness and protocol safety, modernized
fidelity-sensitive DSP and rhythm substrate, and added interactive demos as
repo-owned capability proof.

## Shipped outcomes

- Audit planning surfaces and remediation contract freeze (`g09.001`;
  Contracts `072`–`081` frozen as the remediation baseline).
- Real plugin and device ownership: shared plugin-hosting substrate and
  hardened sandbox execution, real VST3/AU/LV2 discovery with lifecycle
  proof, CoreAudio-backed macOS device truth (`g09.002`–`g09.005`;
  Contracts `072`, `073`).
- Runtime structural repair: shared host/runtime execution and recovery
  unification, runtime interface decomposition and test-surface
  normalization, low-level correctness/safety/protocol hardening
  (`g09.006`–`g09.008`; Contracts `074`, `075`, `076`).
- Fidelity repair: DSP fidelity and semantic-analysis realism uplift,
  rhythm-engine resilience and policy normalization (`g09.009`–`g09.010`;
  Contracts `077`, `078`).
- Interactive proof and release: demo substrate and operator conventions,
  host/runtime/plugin/hardware and DSP/graph/analysis demo suites with audit
  closeout proof, production-readiness grade and release gate,
  operator-visible demo and plugin-browser proof (`g09.011`–`g09.015`;
  Contracts `079`, `080`, `081`).
- Ten strict-lane execution cards (`batch-cards/001`–`010`) carried the
  `g09.006`–`g09.009` lanes; all closed `complete`.
